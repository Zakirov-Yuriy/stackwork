# Stackwork

Площадка IT-вакансий с указанной зарплатой. Сайт на Next.js, API для мобильного приложения на Flutter.
Вакансии двух видов: размещённые работодателями через кабинет (с модерацией) и импортированные из открытых источников удалённых IT-вакансий (с указанием источника и ссылкой на отклик).

## Стек

- **Next.js 16** (App Router, серверный рендер), **React 19**, **TypeScript**
- **Tailwind CSS 4**
- **PostgreSQL 16** + **Prisma 7** (адаптер `@prisma/adapter-pg`)
- **pnpm**

## Запуск на Windows

Нужно поставить один раз:

1. **Node.js LTS** (22.x): https://nodejs.org
2. **pnpm**: в PowerShell `npm install -g pnpm`
3. **Docker Desktop** (для Postgres): https://www.docker.com/products/docker-desktop/

Дальше в терминале VS Code из папки проекта:

```powershell
# 1. Зависимости
pnpm install

# 2. Переменные окружения
copy .env.example .env

# 3. База данных (Postgres в Docker, порт 5432)
docker compose up -d

# 4. Таблицы и демо-данные
pnpm db:migrate
pnpm db:seed

# 5. Dev-сервер
pnpm dev
```

Сайт: http://localhost:3000

### Тестовые аккаунты (создаёт `pnpm db:seed`, пароль у всех `password123`)

| Роль         | Почта                       | Куда ведёт после входа                 |
| ------------ | --------------------------- | -------------------------------------- |
| Администратор | `admin@stackwork.local`     | `/admin`, очередь модерации            |
| Работодатель | `employer@stackwork.local`  | `/employer`, компания «Квант Банк»     |
| Соискатель   | `candidate@stackwork.local` | `/me`, мои отклики                     |

Полный сценарий для проверки: работодатель создаёт вакансию и отправляет на модерацию → администратор публикует → соискатель откликается на странице вакансии → работодатель видит отклик в «Откликах» и меняет статус → соискатель видит статус в «Моих откликах».

Письма в dev-режиме не отправляются, а печатаются в терминал, где запущен `pnpm dev`: строка вида `[mail] to=… subject=… link=…`. Ссылку из неё можно открыть в браузере (подтверждение почты, сброс пароля).

## Письма и защита

- Подтверждение почты при регистрации: пока адрес не подтверждён, соискатель не может откликаться, а работодатель отправлять вакансии на модерацию. Повторная отправка письма из баннера в кабинете.
- Сброс пароля: `/forgot` → письмо → `/reset?token=…`. Токены одноразовые, хранится только sha256, срок 1 час (подтверждение почты: 24 часа).
- Уведомления: работодателю о новом отклике и о решении модерации (с причиной отклонения), соискателю о смене статуса отклика (кроме «просмотрен»).
- Капча Turnstile на регистрации, сбросе пароля, отклике и жалобе; лимиты по IP на вход, регистрацию, сброс, отклики, жалобы.

## Авторизация

- Один вход для всех ролей, роль выбирается при регистрации (`CANDIDATE` или `EMPLOYER`). `ADMIN` назначается только через базу или сид.
- Сессия: JWT (HS256, `jose`) в httpOnly cookie `sw_session` на 30 дней. Секрет в `SESSION_SECRET` (`.env`).
- Тот же JWT принимается в заголовке `Authorization: Bearer …` (для мобильного API; эндпоинт выдачи токена ещё не сделан).
- Пароли: `scrypt` из `node:crypto`, формат `scrypt$salt$hash`.

## Языки

Сайт на русском и английском (next-intl). Русская версия без префикса (`/vacancies/go-developer`), английская с `/en` (`/en/vacancies/go-developer`): у каждой страницы свой адрес, поэтому Google и Яндекс индексируют обе версии, sitemap и hreflang это описывают.

- Язык первого захода: префикс в адресе, иначе cookie `NEXT_LOCALE`, иначе язык браузера. Браузер без русского (английский, турецкий, любой другой) получает `/en`; выбор в переключателе RU | EN в шапке запоминается в cookie. Логика в `src/proxy.ts`.
- Переводы в `messages/ru/*.json` и `messages/en/*.json`, один файл на раздел (`common`, `home`, `vacancy`, `company`, `auth`, `employer`, ...). В коде: `getTranslations("home")` на сервере, `useTranslations("home")` в клиентских компонентах.
- Подписи enum-ов и форматы (зарплата, даты, «3 дня назад») в `src/lib/labels.ts`: `makeLabels(locale)`.
- Письма уходят на языке, в котором пользователь работал на сайте (`src/lib/mail.ts`).
- Тексты вакансий и компаний не переводятся: импортные вакансии на английском, от работодателей на русском. Юридические документы (политика, согласие, соглашение) только на русском, в английской версии над ними плашка.
- Админка только на русском и вне языковых маршрутов (`/admin`).
- Новый язык: код в `src/i18n/routing.ts`, папка `messages/<код>/` с теми же файлами, подписи в `LOCALE_LABEL`, строки в `DICT` в `labels.ts` и `TEXT` в `mail.ts`.

## Поиск

Полнотекстовый поиск Postgres с русской морфологией: колонка `Vacancy.search` (tsvector, GENERATED) с весами (название A, направление и город B, описание C) и GIN-индексом; запрос через `plainto_tsquery('russian', …)`. Плюс точное вхождение по названию компании и технологиям. Миграция `v2_tokens_saved_reports_fts` содержит SQL колонки.

## Жизненный цикл вакансии

`DRAFT` → `MODERATION` → `PUBLISHED` (или `REJECTED`) → `ARCHIVED`

- Черновик сохраняется в любом виде.
- На модерацию уходит только вакансия, прошедшая чек-лист: название от 8 символов, зарплатная вилка, минимум 3 технологии, заполнены «задачи» и «что важно», нет требований к возрасту и полу.
- Правки опубликованной вакансии применяются сразу, без повторной модерации.
- В поиске и API показываются только `PUBLISHED`.

## API v1

Все ответы JSON, кодировка UTF-8.

**`GET /api/v1/vacancies`** — список с фильтрами и пагинацией.

Параметры: `q`, `city`, `format` (REMOTE | HYBRID | OFFICE), `grade` (JUNIOR | MIDDLE | SENIOR | LEAD),
`exp` (NONE | ONE_TO_THREE | THREE_TO_SIX | SIX_PLUS), `employment` (FULL_TIME | PART_TIME | CONTRACT),
`salary` (число), `skills` (slug-и через запятую), `sort` (date | salary), `page`.

Несколько значений можно передавать через запятую или повтором параметра: `?grade=MIDDLE,SENIOR` или `?grade=MIDDLE&grade=SENIOR`.

```json
{
  "items": [{ "id": "…", "slug": "…", "title": "…", "company": {…}, "salary": {…}, "skills": [...] }],
  "page": 1, "pageSize": 20, "pages": 1, "total": 6
}
```

**`GET /api/v1/vacancies/:slug`** — карточка: всё из списка плюс `company` (полная), `description` (разделы, у вакансий работодателей), `descriptionHtml` (одним блоком, у импортированных) и `similar` (похожие).

У каждой вакансии есть `source` (`MANUAL` или источник импорта), `sourceLabel`, `externalUrl`, `applyUrl` (куда вести отклик у импортированных), `language`, `locationNote` и `salary.period` (`MONTH` | `YEAR` | `HOUR`); у компании `logoUrl`.

Ошибки: `{ "error": { "status": 404, "message": "…" } }`.

## Изменение схемы базы

1. Правим `prisma/schema.prisma`
2. `pnpm prisma migrate dev --create-only --name имя` и смотрим SQL: Prisma не умеет генерируемую колонку `Vacancy.search` и каждый раз пытается удалить её индекс и default. Эти строки (`DROP INDEX "Vacancy_search_idx"`, `ALTER COLUMN "search" DROP DEFAULT`) из миграции нужно убрать, иначе она упадёт.
3. `pnpm db:deploy`, клиент перегенерируется через `pnpm db:generate`

## Импорт вакансий

Источники: открытые JSON API площадок удалённых вакансий (Jobicy, Remote OK, Himalayas, Arbeitnow, Remotive), открытые данные «Работы России» (trudvsem.ru, русскоязычные вакансии, фильтры «только удалённые» и «языки» к ним не применяются), тред Hacker News «Who is hiring» (официальный API) и открытые доски вакансий работодателей в Greenhouse, Lever, Ashby и SmartRecruiters (около 240 проверенных досок по умолчанию, список правится в админке; возраст публикации для досок не ограничивается, доски обходятся по кругу, если за запуск не успевают все). Лимит времени на Vercel: недообработанное уходит в следующий запуск; разово заполнить базу целиком можно из консоли без ограничения времени: `pnpm jobs:import` (с `DATABASE_URL` рабочей базы). Уже загруженные вакансии полностью пересинхронизируются раз в три дня, в остальные дни только отмечаются как живые. Закрытые вакансии остаются доступны по прямой ссылке со статусом «закрыта» (noindex, без разметки JobPosting) и списком похожих. hh.ru не используется: с апреля 2026 его API закрыт для анонимного доступа, а условия API и пользовательское соглашение запрещают перепубликацию вакансий.

Что делает импорт (`src/lib/import/run.ts`):

1. Забирает вакансии адаптером источника (`sources/*.ts`), не старше `maxAgeDays` и не больше `maxPerSource`.
2. Отбирает IT-роли по названию и тегам (`classify.ts`), при настройке «только удалённые» и «только с зарплатой» отсеивает остальное; язык описания определяется по тексту, по умолчанию берём только английский.
3. Чистит HTML описания (`sanitize.ts`), определяет направление, грейд, опыт и стек по названию, тегам и тексту. Если источник не отдал зарплату отдельным полем, она ищется в тексте описания (`salary-text.ts`: «The base salary range for this position is $217,000 — $303,900 USD», «CAD $181,000 - $241,000», «250 000 – 350 000 ₽»); опционы, бонусы и бюджеты пропускаются. Для уже импортированных вакансий то же делает `pnpm jobs:salary`.
4. Склеивает компании по нормализованному имени (`Company.nameKey`), создаёт карточки с логотипом и пометкой `isExternal`.
5. Создаёт или обновляет вакансию по паре `(source, externalId)`. Новые публикуются сразу или уходят на модерацию (настройка). Вакансия, которую администратор скрыл (`REJECTED`), больше не обновляется и не возвращается.
6. Вакансии, пропавшие из источника дольше `staleDays` адаптера, уходят в архив.

Условия источников соблюдаются на сайте: внизу страницы вакансии строка «По данным …» со ссылкой на источник, кнопка «Откликнуться» ведёт на страницу источника или работодателя. Для досок Greenhouse/Lever/Ashby показываем «вакансия опубликована компанией на своём сайте». Полнотекстовый поиск ищет и по описаниям импортированных вакансий.

Запуск: кнопка в админке (`/admin/import`, выборка идёт после ответа через `after()`), ежедневно по расписанию (`vercel.json` → `GET /api/cron/import` с заголовком `Authorization: Bearer CRON_SECRET`) или из терминала `pnpm jobs:import`. Журнал запусков с цифрами и причинами пропусков: `/admin/import`.

## Админка

`/admin`, доступ только с ролью `ADMIN`. Оформление по мотивам Sneat (как в админке ИКАН): левое меню, тёмная тема (переключатель в шапке, хранится в браузере), карточки-счётчики, таблицы, графики ApexCharts.

- Главная: счётчики, последние изменения, заявки «Это наша компания».
- Статистика: посетители, просмотры, открытия вакансий, отклики и переходы к работодателю, график по дням, какие вакансии смотрят, экраны, откуда пришли, устройства. Считается без cookie: посетитель = хэш(день, IP, браузер, секрет), адрес не хранится, роботы не считаются, дни по Москве.
- Вакансии: поиск, фильтры по статусу и источнику, действия в строке (опубликовать, в архив, скрыть, удалить).
- Модерация: очередь вакансий работодателей с причиной отклонения и письмом, жалобы, импорт (если включена модерация импорта).
- Импорт: карточки источников, запуск всех или одного, журнал.
- Компании: список, заявки работодателей на страницу компании (одобрение привязывает пользователя к компании).
- Пользователи: список, смена роли.
- Настройки: источники, правила отбора, доски работодателей.

## Telegram-канал

Вакансии автоматически уходят в канал (по умолчанию `@stackworkjobs`): после каждого импорта и после одобрения вакансии работодателя. Один пост на вакансию, не больше лимита в сутки (по умолчанию 20), сначала с указанной зарплатой, только свежие (до 7 дней). Remotive в канал не постится: его условия запрещают перепубликацию.

К посту прикладывается карточка-картинка 1200×630 (`/api/og/vacancy/<slug>.png`: логотип, должность, зарплата, стек; она же og:image страницы вакансии). Режим кнопок выбирается в настройках: прямые ссылки «Открыть на сайте» и «Откликнуться» (отклик идёт через `/apply/<slug>`, переход считается в статистике) или через бота (по умолчанию). В режиме бота под постом кнопка «Открыть вакансию», она ведёт в бота (`t.me/<бот>?start=v_<id>`). Бот проверяет подписку на канал через `getChatMember`: подписчику присылает ссылки на страницу вакансии и отклик, остальным предлагает подписаться и нажать «Проверить подписку». Переходы и выданные ссылки считаются в `TelegramPost` и видны в Админка → Настройки → Telegram.

Подключение:
1. В @BotFather: `/newbot`, токен в переменную `TELEGRAM_BOT_TOKEN` (на Vercel: Secret, затем Redeploy).
2. Добавить бота в администраторы канала с правом «Публикация сообщений».
3. Админка → Настройки → Telegram: канал, лимит, источники, галочка «Постить», затем «Подключить бота». Кнопка проверяет токен, ставит вебхук `/api/telegram/webhook` (секрет выводится из `CRON_SECRET`) и проверяет права бота в канале.
4. «Отправить ожидающие вакансии сейчас» публикует накопившееся в пределах дневного лимита.

Код: `src/lib/telegram/` (`api.ts` обёртка Bot API, `post.ts` карточка и очередь, `bot.ts` логика бота, `settings.ts`), вебхук `src/app/api/telegram/webhook/route.ts`.

## Деплой

### Вариант 1: Vercel + Neon (бесплатно)

1. Postgres: создайте проект на [neon.tech](https://neon.tech), скопируйте две строки подключения: pooled (с `-pooler` в хосте) в `DATABASE_URL` и direct в `DIRECT_URL`.
2. Vercel: «Add New Project» → репозиторий GitHub `stackwork`. Framework: Next.js. Build Command уже задана в `vercel.json`: сначала миграции, потом сборка.
3. Переменные окружения проекта: `DATABASE_URL`, `DIRECT_URL`, `SESSION_SECRET`, `CRON_SECRET` (любые длинные случайные строки), `NEXT_PUBLIC_SITE_URL` (адрес сайта, например `https://stackwork.vercel.app`), `CONTACT_EMAIL`, `INDEXNOW_KEY`; при необходимости SMTP, Turnstile, `GOOGLE_SITE_VERIFICATION`, `YANDEX_VERIFICATION`, `GOOGLE_INDEXING_SA_JSON`.
4. Администратор без демо-данных: локально `DATABASE_URL="<строка Neon>" pnpm admin:create admin@example.com "пароль" "Имя"` (в PowerShell: `$env:DATABASE_URL="<строка>"; pnpm admin:create …`).
5. Cron из `vercel.json` подхватится сам: на Hobby запуск раз в сутки, точность ±59 минут. Первый импорт запустите кнопкой в админке.

### Индексация

- `robots.txt` и карта сайта генерируются сами (`src/app/robots.ts`, `src/lib/seo/sitemaps.ts`): `/sitemap.xml` это индекс, части `/sitemaps/pages.xml`, `/sitemaps/vacancies-<n>.xml` (по 2000 вакансий), `/sitemaps/companies.xml`, кеш на час. Админка и кабинеты закрыты от индексации.
- На страницах вакансий разметка schema.org `JobPosting` (блок «Вакансии» в Google), на главной `WebSite` с поиском.
- Подтверждение сайта: добавьте коды из Google Search Console и Яндекс Вебмастера в `GOOGLE_SITE_VERIFICATION` и `YANDEX_VERIFICATION`, после деплоя подтвердите и отправьте `sitemap.xml` в обоих.
- IndexNow: задайте `INDEXNOW_KEY`, новые вакансии после импорта и модерации сразу уходят в Яндекс и Bing.
- Google Indexing API (ускоряет попадание вакансий в Google, официально разрешён именно для JobPosting): сервисный аккаунт в Google Cloud с включённым Web Search Indexing API, его почта добавлена владельцем сайта в Search Console, JSON ключа в `GOOGLE_INDEXING_SA_JSON`. Квота 200 адресов в сутки.

Из России панель Vercel и CLI часто требуют VPN, а у части провайдеров IP Vercel недоступны. Подключите свой домен через Cloudflare (DNS с проксированием), тогда посетители ходят через сеть Cloudflare.

### Вариант 2: VPS в РФ + Docker

```bash
cp .env.example .env            # заполнить SESSION_SECRET, CRON_SECRET, NEXT_PUBLIC_SITE_URL, DOMAIN, POSTGRES_PASSWORD
docker compose -f docker-compose.prod.yml up -d --build
docker compose -f docker-compose.prod.yml exec app ./node_modules/.bin/prisma db seed   # демо-данные и админ (по желанию)
```

Caddy сам получит сертификат для `DOMAIN`. Ежедневный импорт: `crontab -e` → `0 3 * * * curl -s -H "Authorization: Bearer $CRON_SECRET" https://ДОМЕН/api/cron/import`.

## Продуктовые правила, заложенные в код

- Вакансия работодателя без зарплатной вилки не проходит чек-лист модерации. У импортированных вакансий вилка бывает не у всех: настройка «Только с указанной зарплатой» в админке отсекает остальные.
- Фильтр «Удалённо» показывает и вакансии «удалённо или офис».
- Роли пользователей: `CANDIDATE`, `EMPLOYER`, `ADMIN`. Вход один, роль выбирается при регистрации.
